# Approval Gates

Default mode requires explicit approval at each major gate.

## Gate 0 — Discovery & Intelligence
Clarify outcome, audience, message, content/assets, constraints and research needs. Deliver brief, assumptions, evidence log and open questions. Exit when enough is known to propose directions. Ask: **Approve this brief and research basis?**

## Gate 1 — Creative Direction
Present three distinct territories. Each includes name/thesis, rationale, emotional target, narrative, visual grammar, signature moment, interaction/motion, technical demands, risks and trade-offs. Recommend one. Ask which direction to develop.

## Gate 2 — Experience Blueprint
Define information architecture, scene/section purpose, content hierarchy, key frames, storyboard, interaction states, motion choreography, responsive rules, accessibility, tokens, technical plan and acceptance criteria. Ask approval to prototype.

## Gate 3 — Prototype & Creative Validation
Build a representative working prototype focused on high-risk/high-value moments. Use real assets where possible; label placeholders. Inspect actual browser output. Deliver prototype, evidence, critic report, defect log and revisions. Ask approval as production basis.

## Gate 4 — Production & Delivery
Implement approved experience; test responsive behavior, accessibility, performance, browser compatibility, content, SEO, integrations and error states. Deliver implementation, QA report, limitations and handoff. Ask final approval.

For narrow tasks, compress only unnecessary gates and state why. A successful build is not proof of visual quality or production readiness.
