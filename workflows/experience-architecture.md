# Stage 2 — Experience Architecture

Translate the approved creative direction into an implementable visitor experience.

## 1. Define the journey

Map the visitor's likely questions and the sequence that answers them. For a landing page, consider:
- What is this?
- Who is it for?
- Why should I care?
- How does it work?
- What evidence supports the claims?
- What should I do next?

Do not force every page into a fixed section list. Use only sections that serve the story and conversion goal.

## 2. Specify the page

For each section, document:
- Purpose and key message.
- Content and hierarchy.
- Composition and spatial behavior.
- Visual assets needed.
- Interaction and motion.
- CTA or navigation relationship.
- Responsive adaptation.

Define navigation, footer, forms, CTA destinations, and important interaction states.

## 3. Specify motion

Create a motion plan with trigger, behavior, duration/feel, purpose, fallback, and reduced-motion alternative. Avoid scroll hijacking and motion that delays access to essential content.

## 4. Plan implementation

Identify existing components to preserve, new components, assets, fonts, libraries, integrations, and risks. Prefer existing project dependencies and small solutions. Flag missing content or assets rather than filling gaps with invented claims.

## 5. Deliverable and gate

Deliver an Experience Blueprint using `templates/experience-blueprint.md`. Ask for approval before full implementation unless the user explicitly authorizes autonomous progression.
